Frontend context — Piggy Boss

Stack
- React with Vite (TypeScript/JSX). Tailwind CSS is used for styling utilities.

Purpose
- Client application for Piggy Boss: UI, routing, and client-side state for accounts, finance views, planning, and dashboard.

Project architecture
- Feature-based layout under `src/features/`.
  - Each feature folder contains `layouts/`, `pages/`, `components/`, `routes.tsx`, `service.ts`, and `types.ts` when applicable.
  - Example: `src/features/account/` demonstrates the pattern and can be used as a template for new features.
- Shared components and utilities live under `src/shared/` and are reused across features. If a component is needed in more than one feature, move it to `shared`.

Important files
- `src/main.jsx` — app bootstrap.
- `src/app/App.tsx` — top-level app component and providers (auth, theme).
- `src/features/` — feature modules.
- `src/shared/` — reusable components, services (`api.ts`), and styles.

Conventions & patterns
- Prefer feature-local components; extract to `shared/` when reused.
- Routes are defined per-feature in `routes.tsx` and consumed by the app router.
- Services (`service.ts`) in each feature encapsulate API calls and business logic for that feature.

- Styling rule: always use the color tokens and theme values defined in `frontend/src/shared/styles/theme.ts` when selecting colors for components, charts, and UI elements. Do not hardcode color hex values in components; import from the theme file to ensure visual consistency.

- Small CSS edits: prefer using Tailwind utility classes locally inside feature components for small layout and style tweaks. Reserve adding new CSS files or custom classes for reusable patterns or complex styling that can't be expressed succinctly with Tailwind.

Run & dev notes
- Install deps: `cd frontend && npm install`.
- Start dev server: `npm run dev`.
- Build for production: `npm run build`.

Testing & linting
- Use existing lint/config (`eslint`, `prettier`, `tsconfig`) and run `npm run lint` if available.

Acceptance criteria for frontend tasks
- UI changes include accessible markup, responsive styles, and unit or integration tests when appropriate.
