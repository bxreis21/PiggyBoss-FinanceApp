Backend context — Piggy Boss

Stack
- Python 3.9+ (virtualenv) with Django and Django REST Framework (DRF).

Purpose
- Provides the REST API and data model for Piggy Boss: accounts, transactions, planning, dashboard, and user management.

Layout & important folders
- `manage.py` — Django CLI entry.
- `piggyboss/` — project settings and WSGI/ASGI.
- Apps:
  - `account/` — user profiles, authentication, serializers, views.
  - `finance/` — bank accounts, credit cards, bills, transactions.
  - `planning/` — budgeting and plan models.
  - `dashboard/` — aggregation and reporting logic.

Run & dev notes
- Create/activate venv: `python3 -m venv venv && source venv/bin/activate`.
- Install deps: `pip install -r requirements.txt` (or use Pipfile/Pipenv if preferred).
- Run server: `python manage.py runserver`.

Patterns & conventions
- Apps follow standard Django app layout: `models.py`, `serializers.py`, `views.py`, `urls.py`, `tests.py`.
- Keep business logic in `services.py` or app-level modules rather than views when complexity grows.
- Use DRF viewsets/serializers for API endpoints.

Testing
- Run Django tests: `python manage.py test`.

Env vars (do not store secrets here)
- `DJANGO_SECRET_KEY`, `DATABASE_URL`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`.

Acceptance criteria for backend tasks
- New endpoints include serializers, tests, and URL registration.
- Database schema changes include migrations under `migrations/`.
